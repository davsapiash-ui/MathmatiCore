## חלק א: תשתית הזדהות, ניהול תפקידים ואבטחה

### 1. מודול כניסה והזדהות (Login Module Spec)
1. **דרישות:** יצירת שער כניסה מאובטח השומר על פרטיות מוחלטת של הלומד על בסיס מודל VRA דיגיטלי בלבד ומבטיח תחילת עבודה ללא חסמים רגשיים. הממשק כולל כפתור כניסת מורים באמצעות Google SSO בלבד מול רשימה לבנה דינמית ב-Firestore (הכוללת את davsapiash@gmail.com וללא הגבלת דומיין קשיחה), ותהליך כניסת תלמידים מדורג: בחירת בית ספר ביקורת, בחירת כיתה המבקרים, בחירת מספר תלמיד מתוך אחד עד 12, ותיבת קלט נקייה להקלדת קוד הגישה 10203040. חל איסור מוחלט על הצגת רמזים, סיסמאות ברירת מחדל או טקסטים מקדימים בשדות הקלט.
2. **אפיון:** המערכת פועלת במצב Idle עד לזיהוי קליק, ועוברת למצב Auth Redirect באמצעות Google SSO עבור מורים מול אוסף authorized_teachers ב-Firestore, או לתהליך מדורג וחד-כיווני עבור תלמידים (בית ספר -> כיתה -> מזהה תלמיד 1-12 -> קוד גישה 10203040). שמירת student ID מסוג Integer בטווח 1 עד 12 ב-Zustand וב-Local Storage. זמן תגובה לאימות פחות מ-200ms, שטחי הקלקה בגודל 48px לפחות, ומנגנון Throttle של 500ms על כפתורי הבחירה.
3. **מניע פדגוגי:** כניסה אנונימית נטולת סיסמאות מורכבות מפחיתה עומס קוגניטיבי מחוץ למשימה (Extraneous Cognitive Load) ומונעת חרדת ביצוע עוד בטרם המפגש עם התוכן המתמטי, תוך יצירת מרחב בטוח ללמידה מבוססת VRA digital-first.
* **תרחיש בדיקה קוגניטיבי:** המשתמש מגיע למסך ומבין מיד האם עליו לבחור בנתיב המורה או בנתיב התלמיד מבלי ללחוץ על אלמנטים שגויים.

### 2. מודול מיתוג תפקידים (Role Switcher Module Spec)
1. **דרישות:** מניעת גישה לא מורשית לממשקים שאינם רלוונטיים לתפקיד המשתמש תוך הבטחת עבודה בנתיב מוגדר. חלונית בחירה מרכזית בגודל 600x400 פיקסלים הכוללת שני כפתורי פעולה בולטים המציגים מורה ומנהל, המופיעה רק עבור משתמשים בעלי הרשאות כפולות.
2. **אפיון:** מנוע Zustand מנהל authStore הבודק את הטוקן ואת התפקידים המורשים. במקרה של הרשאה כפולה המערכת עוברת למצב Role Selection. לאחר בחירה, מעדכנת את הסטור הגלובלי וה-JWT ועוברת למצב Route Locked תוך אכיפת React Router Guards והגנה על נקודות קצה ב-Firestore Rules בתוך פחות מ-100ms.
3. **מניע פדגוגי:** הפרדה חדה בין ממשק המורה לממשק התלמיד מונעת הסחות דעת ויזואליות ושומרת על עיקרון הסימטריה הלימודית, כך שהלומד נחשף אך ורק לסביבת העבודה הפדגוגית המותאמת לו.
* **תרחיש בדיקה קוגניטיבי:** האם המשתמש יודע מהו התפקיד שנבחר וכיצד לשנות אותו במידת הצורך בתוך דשבורד המשתמש.

### 3. מודול אבטחה ואנונימיזציה (Zero PII Identity Module Spec)
1. **דרישות:** הבטחת עמידה מלאה בתקני פרטיות חמורים באמצעות אנונימיזציה מוחלטת (Zero PII). חסימה מוחלטת של שדות PII (שם, דוא"ל, טלפון, תעודת זהות) ושימוש במזהים מספריים קבועים בלבד (student ID בין 1 ל-12) עבור כיתות ובתי ספר של קבוצות הביקורת והניסוי.
2. **אפיון:** פילטר אימות קבוע ב-Cloud Functions וחוקי אבטחה קשיחים ב-Firestore הדוחים כל מסמך או בקשת כתיבה המכילים מפתח PII. סכמת ה-DB מאשרת אך ורק שדות מורשים. ולידציה בצד השרת לכל מטעני הטלמטריה מתבצעת בזמן תגובה של פחות מ-50ms.
3. **מניע פדגוגי:** אנונימיזציה מלאה מנטרלת הטיות סובייקטיביות של מורים וציפיות מוקדמות, ומאפשרת הערכה מעצבת אובייקטיבית המבוססת אך ורק על מדדי תהליך ומיקרו-פעילויות קוגניטיביות.
* **תרחיש בדיקה קוגניטיבי:** האם הנתונים הנשלחים מכילים פרטים מזהים בבסיס הנתונים ואם כן האם המערכת עוצרת אותם בזמן.

## חלק ב: ארכיטקטורת בסיס הנתונים וסכמות הנתונים

### 4. סכמת אוספי בסיס הנתונים (Firestore Collections Schema Spec)
1. **דרישות:** הגדרת מבנה נתונים קשיח ב-Firestore המבטיח יציבות, ביצועים גבוהים לאורך זמן ותמיכה מלאה במיון וסינון אנונימי של קבוצות מחקר. האוספים כוללים: classes, students, sessions ו-telemetry_logs.
2. **אפיון:** ניהול סנכרון נתונים אסינכרוני מול Firebase. אוסף classes כולל שדות קשיחים: school_id, class_name ("המבקרים"), ו-class_type (כיתת ביקורת/ניסוי). אוסף students מגביל מזהי תלמידים לטווח 1-12. שימוש ב-Snapshot Listeners ב-Zustand ו-Batch Updates לביצועים אופטימליים עם זמן אחזור מקסימלי של 150ms.
3. **מניע פדגוגי:** ארגון נתונים סדור ומעקב אנונימי מאפשרים לחוקרים ולמורים לזהות דפוסי תפיסה מוטעים (Misconceptions) ברמת הכלל והפרט ללא פגיעה בפרטיות הלומדים.
* **תרחיש בדיקה קוגניטיבי:** האם המידע בבסיס הנתונים תואם את המבנה המוגדר ואם לא האם המערכת מתריעה.

### 5. סכמת נתוני מיקרו פעילות (Telemetry JSON Payload Schema Spec)
1. **דרישות:** איסוף דאטה מדויק המאפשר ניתוח פדגוגי עמוק של כל פעולת למידה. יצירת אובייקט JSON תקני הכולל log ID (String), student ID (Integer 1-12), action type (String), ומצבי ייצוג דיגיטליים בלבד.
2. **אפיון:** Zustand telemetryStore מייצר ומדוחס אובייקט JSON בכל אירוע ממשק לוגי (ללא מעקב עכבר רציף). ולידציית גודל מטען עד 50KB לפני כל שליחה ל-Firestore telemetry_logs. אגירה בתור מקומי במקרה של ניתוק.
3. **מניע פדגוגי:** תיעוד ברזולוציה של מיקרו-אירועים מאפשר לפענח את התפתחות החשיבה המופשטת ואת תהליכי הפריטה וההקבצה בזמן אמת, כחלק מהערכה מעצבת רציפה.
* **תרחיש בדיקה קוגניטיבי:** האם המערכת מצליחה לתעד אירוע למידה בודד ללא אובדן נתונים.

## חלק ג: מרחב הלמידה של התלמיד ומנוע VRA

### 6. מודול לובי התלמיד (Student Hub Module Spec)
1. **דרישות:** הפחתת עומס קוגניטיבי על ידי הצגת מפגש פעיל יחיד בלבד מרשימת 8 המפגשים, באמצעות כרטיס יחיד במרכז המסך (400x200 פיקסלים) ומניעת הסחות דעת.
2. **אפיון:** שליפת אובייקט המפגש הפעיל מתעדכנת מ-Firestore דרך sessionStore ב-Zustand. שאר המפגשים מוגדרים במצב Disabled ומוסתרים לחלוטין מהממשק. מעבר לעמוד המפגש מתבצע בטעינה בודדת וסנכרון ה-Local State.
3. **מניע פדגוגי:** מיקוד קוגניטיבי (Cognitive Focusing) במשימה בודדת מונע הצפה תחושתית ומכוון את הקשב (Attention) של התלמיד לתרגול הנוכחי בהתאם לתאוריית העומס הקוגניטיבי (Sweller).
* **תרחיש בדיקה קוגניטיבי:** האם התלמיד מבין שהכרטיס שמוצג הוא המפגש היחיד והאם הוא יודע איך להתחיל.

### 7. מודול לוח בית המספרים הדיגיטלי (Place Value Chart Module Spec)
1. **דרישות:** מתן ארגון ויזואלי ברור לחישובים מתמטיים מורכבים במודל VRA דיגיטלי בלבד. ארבע עמודות קבועות (150x400 פיקסלים) המציגות את טורי החישוב העשרוניים ללא רמזים או טקסטים מקדימים.
2. **אפיון:** יישום מחלקות CSS לעמעום טורים (brightness 0.6) ונעילת pointer-events בטורים שאינם פעילים בעת חישוב. ניהול הטור הפעיל (activeColumn) ב-Zustand workspaceStore וסנכרון מול ה-Local Storage למניעת עומס חזותי.
3. **מניע פדגוגי:** ייצוג ויזואלי מובנה של מבנה המספר העשרוני מספק פיגום קוגניטיבי (Scaffolding) המסייע להפנמת ערך המקום והקשר בין יחידות, עשרות ומאות.
* **תרחיש בדיקה קוגניטיבי:** האם התלמיד מזהה איזה טור הוא הפעיל ביותר וכיצד הוא עובר בין טורים.

### 8. מודול לבני דינס וירטואליות (Dienes Blocks Engine Module Spec)
1. **דרישות:** המחשת פעולות חשבוניות בצורה מוחשית-וירטואלית המקדמת חשיבה מופשטת על ידי מניפולציה וירטואלית בלבני דינס דיגיטליות, כולל גרירה, פריטה והקבצה, ללא כל תלות בעצמים פיזיים (VRA בלבד).
2. **אפיון:** מנוע גרפי מבוסס HTML5 Canvas / WebGL להצגת הבלוקים הדיגיטליים ב-60fps. ניהול מערך קואורדינטות ב-Zustand dienesStore. יישום מנוע פיזיקלי להצמדה מגנטית (Magnetic Snap) והרחבת שטחי השמיטה ב-30px. תיעוד אירועי PLACE_VALUE_CONVERSION בלוגים.
3. **מניע פדגוגי:** מניפולציה ויזואלית-רפלקטיבית (VRA) מאפשרת למידה חוקרת וגילוי פעיל, ומגשרת באופן ישיר בין הפעולה הפיזית-וירטואלית להבנה המושגית של שיטת המבנה העשרוני.
* **תרחיש בדיקה קוגניטיבי:** האם הלומד מצליח לגרור ולהצמיד את הבלוקים למקום הנכון מבלי שהם יחזרו למקומם בטעות.

### 9. מודול מקלדת דינמית וגשר VRA דיגיטלי (Dynamic Keyboard and VRA Bridge Module Spec)
1. **דרישות:** קלט: במצבי חיבור/הקבצה: סימון 10 לבנים מציג כפתור צף "הקבץ". במצבי חיסור/פריטה: לחיצה עם כלי הפטיש על לבנת עשרת/מאה מפרקת אותה. עיבוד: הרצת אנימציית נדידה ועדכון הלוח הסמלי. פלט: שחרור אירוע PLACE_VALUE_CONVERSION_SUCCESS ופתיחת נעילת המקלדת בטור הפעיל.
2. **אפיון:** ניהול מצבי מקלדת (isKeyboardLocked) ב-Zustand keyboardStore. נעילת המקלדת נותרת פעילה עד לקבלת אירוע PLACE_VALUE_CONVERSION_SUCCESS מ-dienesStore. עיגולי הזיכרון נותרי פתוחים תמיד. זמן תגובה פחות מ-50ms.
3. **מניע פדגוגי:** נעילת המקלדת מחייבת את התלמיד לבצע ראשית את ההמרה הויזואלית-מורגשת, ובכך מונעת פתרון פרוצדורלי טכני ומבטיחה הבנה מושגית מעמיקה של תהליכי הפריטה וההקבצה.
* **תרחיש בדיקה קוגניטיבי:** האם הלומד מבין מדוע המקלדת נעולה ואיזו פעולה הוא צריך לבצע כדי לשחרר את הנעילה.

### 10. מודול לוח חיבור אדפטיבי מבוקר (Symmetrical Addition Grid Module Spec)
1. **דרישות:** קלט: אירועי גרירה, פטיש, הקלדה או ביטול. עיבוד: הפעלת טיימר פנימי לטור הפעיל המתאפס בכל אירוע. במידה וחולפות 45 שניות ללא קלט, נפלט אירוע HESITATION_TRIGGER. פלט: הצגת כרטיס החניכה הסוקרטי בחלונית צדדית שקטה ללא חלונות קופצים.
2. **אפיון:** ניהול טיימר השהייה ב-Zustand timerStore. עם הגעה ל-45 שניות ללא אירוע ממשק, נפלט HESITATION_TRIGGER המעדכן את socraticStore. נראות הלוח מנוהלת ב-Framer Motion עם Fade In של 2500ms ו-Fade Out של 3000ms בעת הקלדה מוצלחת.
3. **מניע פדגוגי:** זיהוי השהייה ממושכת מונע תסכול ותחושת אובדן אונים נרכש, ומגיש תמיכה בזמן אמת (Just-in-Time Scaffolding) בדיוק ברגע בו הלומד זקוק להכוונה קוגניטיבית.
* **תרחיש בדיקה קוגניטיבי:** האם הלומד מבין מתי הלוח מופיע ומתי הוא נעלם.

---

### 11. מודול כפתור ביטול פעולה פדגוגי (Undo Action Engine Module Spec)
1. **דרישות:** חיזוק החוסן הרגשי על ידי מתן לגיטימציה לטעות והפיכתה. כפתור Undo ייעודי בפינה הימנית העליונה (48x48 פיקסלים) המאפשר ביטול לפעולות קודמות ללא הגבלה, ללא הורדת ניקוד וללא חיווי ענישתי או פגיעה בטלמטריה.
2. **אפיון:** ניהול מחסנית מצבים (historyStack) ב-Zustand undoStore. בלחיצה על undo, המערכת משחזרת את המצב הקודם של הבלוקים והזנות הטקסט ללא רישום דגלי שגיאה בטלמטריה וללא שינוי מדדי הצלחה.
3. **מניע פדגוגי:** הפיכות (Reversibility) של פעולות מפחיתה חרדת טעויות, מעודדת ניסוי וטעות חוקר, ומפתחת תחושת מסוגלות עצמית (Self-Efficacy) בלמידת מתמטיקה.
* **תרחיש בדיקה קוגניטיבי:** האם הלומד יודע כיצד לבטל את הפעולה האחרונה ללא חשש מתוצאות.

## חלק ד: מנוע החניכה הסוקרטי ומפרט אינטגרציית ג'מיני

### 12. מודול חונכות סוקרטית ובלימת ניחושים (Socratic Mentoring Module Spec)
1. **דרישות:** קלט: אינטראקציות לומד או הקלקה על מסיח שגוי בכרטיס הסוקרטי. עיבוד: הפעלת טיימר 45 שניות להשהייה, ונעילת לחצני הבחירה בכרטיס ל-60 שניות בעת מענה שגוי. פלט: הצגת כרטיס סוקרטי בצד, צביעת מסיח שגוי באדום, עמעום שאר הלחצנים (40% שקיפות, cursor not-allowed), והצגת שעון חול דיגיטלי.
2. **אפיון:** Zustand socraticStore מנהל את המצב socraticState. בחירת מסיח שגוי מפעילה חסימה של 60,000ms השמורה גם ב-Local Storage לשרידות ברענון מסך. סרגל התקדמות/שעון חול מציג את הזמן הנותר תוך שמירה על מרחב העבודה הראשי פתוח לתרגול.
3. **Strict Bilingual Developer Instructions:** Eradiate all CRA terminology and physical object references. All design specifications and code structures must implement the VRA model only. Track user interaction events (drag, hammer, typing, undo) to reset internal timer, firing HESITATION_TRIGGER after 45 seconds of input inactivity to display socratic card in a side pane without popups. Upon selecting an incorrect distractor inside the socratic card, apply a 60 second block on all socratic selection buttons, style the chosen option with red background and error icon, set disabled state (40% opacity, not-allowed cursor) on remaining buttons, and display a digital hourglass with a gentle hint suggesting the undo button, while keeping the main workspace fully operational.

### 16. מודול לוח רפלקציה תלת שלבי (SRL Reflection Board Module Spec)

### 29. מודול ניהול מצב גלובלי ומכונות מצבים (Zustand and State Machines Spec)
1. **דרישות:** הבטחת עקביות ממשק מלאה, ניהול מצבי יישום גלובליים ומעברים דקלרטיביים בין הסטור של סביבת העבודה, המורה וההרשאות.
2. **אפיון:** ארכיטקטורת ניהול מצב מבוססת Zustand עם Decoupled Stores. פונקציות מעבר מצב מנוהלות בצורה דקלרטיבית ומעודכנות על בסיס אירועי טלמטריה.
3. **Strict Bilingual Developer Instructions:** Architect a modular client global state using Zustand. Keep workspace store, teacher store, and authentication credentials store decoupled. Write robust state transition functions using declarative frameworks to manage UI state changes based on non-nullable telemetry input actions.
4. **מניע פדגוגי:** ניהול מצב יציב ומסונכרן היטב מונע שגיאות ממשק, מבטיח חוויית משתמש רציפה (Seamless UX) ומחזק את האמון של התלמיד והמורה במערכת הדיגיטלית.
